# 应用生命周期

由装配入口推进生命周期。服务和组件负责报告它们实际拥有的资源与运行状态。探针将进程存活和应用能接收请求分别对外发布。

| 阶段 | 对外行为与处置 |
| --- | --- |
| 启动 | 校验配置，按依赖顺序取得资源并注册服务。必需组件可用后才发布就绪。部分启动失败时，逆序释放已移交资源，记录启动首因和清理错误。 |
| 运行 | `/livez` 表示进程可响应存活探测。`/readyz` 表示实例具备接收请求的条件。依赖故障对就绪的影响由已声明的接入前提决定。 |
| 重载 | 显式启用时由新进程继承监听器，就绪后接流，旧进程按关停预算排空。候选启动失败由当前进程记录并继续服务。[优雅重载](../design/graceful-reload.md) |
| 摘流 | 收到 `SIGTERM` 后撤销就绪，应用入口按契约限制新工作。在途请求和 Agent 流在剩余预算内完成，预算耗尽时传播取消。 |
| 退出 | 按依赖顺序回收资源，保留清理结果。未完成工作或无法确认的外部工具效果交给有权处置的一方。 |

第三方执行回调和容器运行环境的退出预算需要在实现前对齐。通过故障注入和真实容器停止信号分别验证启动失败、摘流延迟、在途取消与有界退出。测试入口见[首版落地设计](../design/first-vertical-slice.md)。
