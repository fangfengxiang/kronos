# ADR 0004 职责层与 Go 模块边界

**状态。** 采纳四个基础层目录与独立封装模块。业务为第五层，由参考应用承载。

## 决定

- `core/`、`infra/`、`framework/`、`platform/` 分别承载核心原语、外部适配、应用运行和平台约定。每个独立封装包包含自己的 `go.mod`。同一能力的私有实现、测试和测试资源随该模块维护。
- 封装模块使用 `github.com/fangfengxiang/kronos/<目录>` 路径。现有 `core/runtime` 和 `core/locale` 保留原导入路径。根 `go.mod` 维护参考应用及仓库级 Go 验收代码，开发工作区通过 `go.work` 串联模块。Go 版本基线是 1.25.0。

## 依赖方向与注入

下表约束同一仓库内跨层的 Go import。外部 SDK 的使用限于负责接入的包。

| 包所在位置 | 可以导入的其他层 |
| --- | --- |
| `core/` | 无。核心原语可独立运行和测试。 |
| `infra/` | `core/`。适配包通过自己的公开方法满足消费方契约。 |
| `framework/` | `core/`。可选基础设施通过框架消费方的接口接入。Kratos 的具体类型留在对应传输实现和装配边界。 |
| `platform/` | `core/`、`infra/`、`framework/` 中需要使用的公开包。 |
| 应用装配入口 | 按需使用上述四层和该应用的业务实现。 |

消费包定义它实际需要的窄接口。应用装配入口创建具体实例，通过构造参数或明确的注册接口注入，并负责配置、启动和资源释放。框架装配可以管理已交接组件的生命周期。依赖缺失或装配失败通过显式错误报告。

例如，框架只调用自己需要的配置读取方法。应用入口创建文件或远程配置适配，再把实例交给框架。基础设施包通过 Go 的接口满足关系接入，无需导入框架来声明实现。测试可以在相同接入点注入内存替身。

跨层共享能力以实际消费者需求为依据，保持语义稳定、接口窄和实例独立。避免借助全局单例、`init()` 或服务定位器隐藏依赖。

## 取舍与发布

独立模块让消费者选择所需组件，并让外部 SDK 的版本约束跟随适配模块。代价是每个模块维护依赖、版本标签和消费验收。发布标签按 Go 子模块规则使用目录前缀，例如 `core/runtime/v0.1.0`。组件依赖已发布的版本。参考应用在组件尚无版本时可用局部 `replace` 接工作树，发布态消费验收使用真实版本。[Go Modules Reference](https://go.dev/ref/mod)

## 验收

CI 使用 Go 验收入口遍历各模块，在 `GOWORK=off` 下运行独立测试并检查依赖图。跨模块用例在组装模块中验证。参考服务的业务与命令包额外检查直接导入，Kratos 与 gRPC 库的导入位于私有绑定和生成代码。接入已发布版本时，从单独的消费者模块核对实际解析的版本、编译和调用结果。[原生 Go 验收](../design/go-verification.md)

CI 按 SDK 导入前缀和适配模块的所有权校验生产代码。Kronos 的运行、日志、追踪和专用监听适配可以使用各自依赖的 Kratos 能力，参考服务只在私有传输和生成代码导入 Kratos 或 gRPC。应用业务和命令通过 Kronos 访问已接入的模型、存储、注册、消息及观测能力。标准 Protobuf 库可以用于业务协议。原生对照测试可直接使用 SDK，以便核对适配结果。[SDK 归属与验收](../design/go-verification.md#外部-sdk-归属)
