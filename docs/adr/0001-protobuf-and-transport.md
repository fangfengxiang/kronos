# ADR 0001 协议定义与传输映射

**状态。** 采纳协议优先、Kratos 底座与双入口共用实现。首条纵切的路由与生成方式见 [Assistant v1 协议设计](../design/assistant-protocol.md)。部署拓扑随应用切面验收。

## 背景

调用方需要从同一份契约获得服务名、方法名、请求和响应类型。内部服务使用 RPC，支持浏览器或既有 HTTP 客户端的方法需要可审查的 HTTP 映射。

## 决策

- 用版本化 Protobuf `service`、`rpc` 与 `message` 定义契约。通过显式 `google.api.http` 注解声明需要对外开放的方法，评审路径、方法、请求来源、错误和访问边界。
- 使用 Kratos 承载 gRPC 和 HTTP。生成消息、gRPC 存根和 HTTP 绑定，由应用装配将两种入口连接到同一个服务实现。Go 公开契约从同一份描述符生成消息别名和一元接口。生成产物随协议变更一起验证。[公开契约生成](../design/protobuf-go-contract.md)
- 在服务实现或两种入口均能经过的中间层放置共享授权、业务校验及错误分类。各传输负责解码、认证材料提取、请求上下文和状态映射。

## 取舍

首个切片按同进程装配验证，调用少一次网络中转。HTTP 直达实现时须验收共享行为，因为 gRPC 拦截器只覆盖 gRPC 入口。出现独立发布或网络隔离要求时，再对照独立网关的部署、认证传播和故障成本。

## 验收

同一请求分别走真实 gRPC 和显式 HTTP 入口，核对等价响应、拒绝原因及取消传播。确认缺少 HTTP 映射的方法不会被 HTTP 路由注册。校验生成结果可复现，发布基线建立后，用旧客户端和新服务组合验证兼容性。
