# ADR 0008 Kafka 确认与消费位点

**状态。** 采纳同步确认的生产与处理成功后的消费位点推进，用 TextBackend 事件验证。

## 决定

- 适配使用 Kafka 原生的确认与消费组位点。生产使用 `acks=all` 和客户端幂等设置，调用的成功返回体现 broker 已确认。调用方超时表示停止等待，业务按不确定结果设计重试。
- 组内每轮拉取一条记录。持有该分区时完成处理，成功后同步提交位点，再允许分区再平衡。任一记录处理失败时结束本轮，之后由同组实例从最后成功提交的位置继续。处理已生效、确认位点失败或进程中断时可能重复投递。
- 启用事件的 TextBackend 按业务顺序执行生成、发布和 RPC 返回。事件体由该服务的 Protobuf 定义，Kafka 适配独立于消息序列化。消费命令输出成功后才推进位点。请求标识可关联记录，重复调用仍可能共享一个请求标识。

## 取舍与验证

异步发送能降低单次 RPC 等待，同步确认便于按调用观察事件写入结果。自动提交可简化轮询，显式提交使消费函数成功与位点推进的关系可验收。与数据库或其他外部系统协调原子副作用时，需由相应业务定义持久化与去重。当前事件记录通过实际 broker、失败前后重复消费和真实进程验收。[Apache Kafka 投递语义](https://kafka.apache.org/22/design/design/#semantics) · [Kafka 消息与文本生成事件](../design/kafka-generation-events.md)
