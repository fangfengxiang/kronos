# ADR 0003 语言协商与稳定错误

**状态。** 采纳 HTTP、SSE、标准 gRPC 与 MicroRPC 的统一语言协商。Assistant 首个消费者支持 `en` 和 `zh-Hans`，默认 `en`。

## 背景

HTTP 和 gRPC 的调用方可能提交不同形式的语言偏好。用户需要可读提示，程序需要在翻译变化后仍能识别同一种失败。

## 决策

- 入口根据请求偏好和受支持集合匹配语言标签。HTTP、SSE 与 MicroRPC 使用 `Accept-Language`，标准 gRPC 使用 `accept-language` 元数据。各入口共用权重和默认回退规则。发起下游调用时，由调用方设置出站偏好。应用向需要渲染的资源传递选定语言标签。[框架语言协商](../design/framework-localization.md)
- 由消息资源所有者按稳定消息键渲染文案。支持中文与英文资源，并为不支持的偏好、缺少的翻译和缺少偏好设定可验证的回退。
- 稳定错误码和传输状态分别表达语义及适配结果。调用方依据错误码处理失败。人类可读的消息允许按语言变化。语言、地区和时区各自从其权威来源取得。

## 取舍

入口选择语言可避免下游重复解释长偏好列表。应用与 Agent 各自拥有内容和格式规则。将错误资源分开维护，可独立调整文案并保持客户端分支兼容。

## 验收

从 HTTP、SSE、标准 gRPC 与 MicroRPC 验证匹配与回退一致，核对错误码在翻译切换或缺失时保持稳定。用带地区子标签、权重并列及入站与出站并存的输入验证优先级。
