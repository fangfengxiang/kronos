# ADR 0003 语言协商与稳定错误

**状态。** 采纳从首版覆盖中文和英文。默认语言、支持的完整标签、gRPC 元数据键及偏好来源优先级待首个切片确认。

## 背景

HTTP 和 gRPC 的调用方可能提交不同形式的语言偏好。用户需要可读提示，程序需要在翻译变化后仍能识别同一种失败。

## 决策

- 入口根据请求偏好和受支持集合匹配语言标签。HTTP 使用 `Accept-Language`，gRPC 采用明确定义的元数据入口。应用向需要渲染的资源传递选定语言标签。
- 由消息资源所有者按稳定消息键渲染文案。支持中文与英文资源，并为不支持的偏好、缺少的翻译和缺少偏好设定可验证的回退。
- 稳定错误码和传输状态分别表达语义及适配结果。调用方依据错误码处理失败。人类可读的消息允许按语言变化。语言、地区和时区各自从其权威来源取得。

## 取舍

入口选择语言可避免下游重复解释长偏好列表。应用与 Agent 各自拥有内容和格式规则。将错误资源分开维护，可独立调整文案并保持客户端分支兼容。

## 验收

从 HTTP 和 gRPC 分别请求中文、英文、带地区子标签的语言和不支持的语言。验证匹配与回退一致，并在两个入口核对错误码在翻译切换或缺失时保持稳定。用两种偏好来源并存的输入验证确定后的优先级。
