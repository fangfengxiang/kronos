# ADR 0010 公开 RPC 契约兼容

**状态。** 采纳 Proto 兼容门禁和面向消费者的 Go 签名检查。

## 决定

版本化 Proto 拥有服务名、方法名、消息及传输字段。当前版本的服务和调用方需要在滚动部署期间互通。兼容变更沿现有版本演进。需要改变既有线协议或调用语义时，由协议所有者定义新的版本并规划双版本迁移。

使用当前锁定的 Buf 版本按 `FILE` 规则检查 Protobuf。它保护线协议、JSON 字段以及 Go 生成消费者所依赖的名称与文件。通过 `go run ./platform/verify breaking <提交>` 显式传入基线，工具读取 Git 保存的快照。CI 的推送事件使用推送前提交，PR 使用目标提交。Go 源码由独立消费者测试编译公开装配、调用签名及资源关闭契约。既有官方旧协议联调继续验证真实运行语义。[Buf 兼容检查](https://buf.build/docs/breaking/usage/) · [Go 兼容策略](https://go.dev/blog/compat)

## 取舍与证据

复用 Git、Buf 和 Go 类型系统。生成一致性、编译兼容及协议互通分别在其对应边界验证。基线获取错误使检查失败。新增服务从加入兼容基线后按同样规则保护。

本地测试创建临时 Git 仓库，验证兼容的新增字段通过、改变已有字段类型被拒绝。实际工作树以 Git 快照执行同一命令。外部包编译断言覆盖公开入口和关闭契约。[命令和结果](../design/go-verification.md)
