# 首条纵切

首条纵切用一个可确定复现的 Assistant 服务验证 Protobuf 契约、多种调用入口、Agent 流式执行、本地化和容器生命周期。标准调用入口和兼容监听复用同一应用装配。Blades、本地化及容器行为随对应组件验收。[Assistant v1 协议设计](assistant-protocol.md) · [应用装配与关停](app-lifecycle.md) · [SSE 与 go-micro v2 监听](additional-listeners.md)

## 调用走向

| 客户端入口 | 方法 | 负责边界 |
| --- | --- | --- |
| gRPC unary | `Assistant.Run` | gRPC 适配器解码并调用共享用例。 |
| HTTP JSON | `POST /v1/assistant:run` | 从同一份 Proto 的 HTTP 注解生成绑定，调用同一用例。 |
| gRPC server stream | `Assistant.StreamRun` | 接收一次请求，按顺序发送同一用例公开的事件。 |
| SSE | `POST /v1/assistant:streamRun` | 专用监听器使用生成绑定交付同一流式用例。 |
| go-micro v2 RPC | `Assistant.Run` | 专用监听器转换旧信封并调用一元用例。 |

`Assistant` 的方法名、请求、响应和事件由 Proto 定义。应用用例拥有业务行为和错误语义。Kratos 适配负责传输、错误映射和请求上下文，旧协议适配负责兼容信封。 [协议与传输决定](../adr/0001-protobuf-and-transport.md)

## 确定性的 Agent

应用装配入口已选择本地确定性模型替身，并通过 Blades 适配器接入一元和流式调用。测试可控制替身发出的文本片段、失败时机和取消回执。计划中的 Compose 只运行应用容器，无需外部模型账户或 API Key。[Blades 文本 Agent 适配](blades-adapter.md)

1. `Run` 返回固定测试输入对应的最终结果。HTTP JSON 和 gRPC 客户端用各自的生成类型读取同一业务结果。
2. `StreamRun` 发送有序增量，成功时恰有一个成功终态。客户端取消后，观察模型替身收到取消并退出。
3. 已发送部分结果后发生上游错误时，客户端能区别错误终止与成功完成。慢消费者的等待有界，终止后请求与产出端都能收尾。

公开事件包含客户端需要的状态。Blades 内部事件与模型供应商类型在适配层转换。工具、会话持久化和中断恢复留到有相应验收场景时再设计。 [Agent 流式决定](../adr/0002-agent-stream.md)

## 语言与反馈

首版验收覆盖简体中文和英文。HTTP 与 SSE 从 `Accept-Language` 获取偏好，gRPC 使用 `accept-language` 元数据。Assistant 的空提示词文案已接入 `en` 和 `zh-Hans`，默认英文。消息目录为缺少的译文提供默认资源回退。[框架语言协商](framework-localization.md)

对同一次失败分别请求两种语言。机器可判断的错误码保持一致，人类可读的系统消息随所选语言变化。Agent 输出语言由请求意图和模型任务确定。分别验证系统文案与 Agent 输出语言的选择，并确认两种语言的事件结构、顺序和终态一致。 [本地化决定](../adr/0003-localization.md)

## 容器生命周期

1. 应用进程启动后通过 `/livez` 报告存活。待监听和必要组件准备完成，再通过 `/readyz` 报告就绪。
2. 向容器发送 `SIGTERM`。观测就绪撤销，核对新的调用按约定拒绝。在途工作在约定期限内完成或收到取消，进程随后退出。
3. 令一个组件启动失败。验收未发布就绪、已取得资源被回收，日志能定位启动首因和清理异常。

探针体现接流条件。结构化日志记录启动、终止与错误的验收证据。Compose 只用于验证镜像与进程边界，集群服务发现和流量摘除由将来的部署环境验证。 [架构概览](../architecture/overview.md)

## 持续集成验收

| 层次 | 拟议检查 | 通过证据 |
| --- | --- | --- |
| 协议 | 检查 Proto 规范，使用固定生成工具重复生成。 | 生成结果一致。发布基线确定后增加兼容差异检查。 |
| 单元 | 用确定性替身测试调用、事件映射、语言协商、取消和资源释放。 | 断言关键顺序与结果，执行 Go 竞态检查。 |
| 集成 | 启动实际 gRPC、HTTP、SSE 与 go-micro v2 监听，覆盖成功及错误路径。 | 核对共享用例结果、错误映射和流取消。本地化验收覆盖语言回退。 |
| Compose 端到端 | 构建镜像并等待探针就绪，调用实际入口，再发送停止信号。 | 验证探针、生效配置和有界退出。失败时保留日志及容器状态供定位。 |

计划用同一套本地与 CI 步骤执行 `docker compose up --build --wait`、入口探测和有期限的停止。先采集失败证据，再清理容器。首次实现时补齐具体端口、构建入口、超时和预期输出。
