# 语言匹配与消息资源

[本地化 ADR](../adr/0003-localization.md)要求入口共享语言协商，同时允许资源所有者维护文案。Core 交付两个独立能力。上层可只使用语言匹配，也可将选定语言交给消息目录。

## 语言匹配

- 构造时从使用方接收支持语言和默认语言。默认值须在支持集合内。识别无法解析或缺少具体语言的标签，以及规范化后的重复项。配置验证成功后可以并发共享同一个实例。
- 调用方将候选标签按明确优先级依次传入。优先选择第一个高置信度或精确的匹配。忽略无效候选，全部没有匹配时使用配置的默认值，并报告发生了回退。
- 输出是已登记的规范标签。地区推断和 Unicode 扩展不会产生额外资源键。默认语言在匹配等价时优先，其余登记项保留传入顺序。
- 标签按 BCP 47 规范化。登记配置会拒绝等价重复，例如 `en-US` 与 `en-Latn-US`。语言资源键接受语种、书写体系及地区等语言标识，扩展字段只可出现在请求偏好。简体与繁体保持为不同的资源键。
- HTTP 权重和零权重过滤、gRPC 元数据、用户配置和偏好来源的优先级由调用边界确定。

简单按字符串截断很难识别 `zh-TW` 应用繁体资源，也容易在变体相近时选错语言。采用 Go 扩展库的 BCP 47 语言匹配和 CLDR 数据，显式关闭仅按书写体系匹配，丢弃低置信度结果。先看用户给出的候选顺序，再用库处理每个具体候选的近似。通过库返回的索引取已登记标签，避免把推断地区与格式扩展混入资源身份。这一策略借鉴了优先列表的处理方式，具体匹配由 Go 库实现。[Go 语言匹配](https://go.dev/blog/matchlang) · [Matcher 行为](https://pkg.go.dev/golang.org/x/text/language#Matcher) · [RFC 4647 优先查找](https://www.rfc-editor.org/rfc/rfc4647.html#section-3.4)

## 消息资源

- 资源维护方注入各语言的稳定键到文本映射。目录构造时校验标签属于支持集合、默认语言资源已登记、消息键非空，并复制资源。构造期间由调用方持有输入。发布后以并发只读方式使用。更新资源时，由上层构造并安全发布新快照。
- 给定已选规范标签和消息键，先查该语言，再查目录默认语言。返回正文与实际采用的语言。两处都缺键时报告缺失。显式配置的空文本按命中处理。
- 调用方保留原始消息键和错误信息。模板、复数、日期、货币格式化与 Agent 输出策略各由使用方决定。

Go 的消息目录提供模板和更丰富的语言格式化。首版资源契约只需稳定键、明确回退和实际语言，使用只读数据结构直接表达。出现格式化场景时，使用方可接入 Go 文案工具。[Go 消息目录](https://pkg.go.dev/golang.org/x/text/message/catalog)

## 验收

- 验证简繁体与地区标签、候选优先级、畸形候选后的继续匹配、低置信度回退和扩展字段归属。
- 验证目录快照、实际采用的语言、缺失键和显式空文案。用一个可运行的包级示例走完匹配到渲染数据的路径。
- 以重复请求为负载分别观察规范标签匹配、地区匹配与文案查找的开销。实际 HTTP、gRPC 和 Agent 输出覆盖留在首条服务纵切。

## 性能复盘

Go 1.25.0、macOS arm64 的小型包级基准使用 `go test ./core/locale -run '^$' -bench . -benchmem -benchtime=300ms -count=3`。登记语言的基准从约 158–182 ns/op、4 次分配改善到约 6.3–6.5 ns/op、零分配。实现先精确查已有登记表，地区变体仍进入同一匹配规则。地区标签基准约 357 ns/op。目录命中和默认回退分别约 7–8 和 16–17 ns/op，两种查找均为零分配。这些数据用于判断包级开销，服务延迟由应用纵切衡量。
