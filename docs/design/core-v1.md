# Core 首版落地设计

首版范围从[参考应用](first-vertical-slice.md)的调用和验收反推。Core 提供与进程装配、具体传输和业务策略相互独立的原语。配置和依赖由使用方传入。

| 顺序 | 切面 | 使用方与完成证据 |
| --- | --- | --- |
| 1 | goroutine 执行边界 | 上层能独立获得任务终态与 panic 诊断。日志或恢复回调自身终止时，观察者仍能收到原任务结果。见 [Runtime Go](runtime-go.md)。 |
| 2 | 语言匹配 | gRPC、HTTP 或 Agent 的上层统一传入有序偏好。选择稳定的受支持语言，同时区分命中与默认回退。见[语言匹配和消息资源](core-localization.md)。 |
| 3 | 消息资源 | 资源所有者注入文案快照，按稳定键查找。查找结果注明实际文案语言，缺失可交由应用处置。见[语言匹配和消息资源](core-localization.md)。 |
| 4 | 时区转换 | 用事件绝对时刻和显式 IANA 时区计算当地日期与偏移。加载错误可识别，精简部署可在应用构建时内嵌规则。见[Core 时区](core-timezone.md)。 |

## 边界与取舍

- 并发原语负责执行与报告。跨任务等待、取消和首错策略跟随应用的所有者，已有 Go 标准能力可直接组合。[Go context](https://pkg.go.dev/context) · [Go sync](https://pkg.go.dev/sync)
- 语言、地区、时区、计量和 Agent 输出语言各有配置权威。Core 从已排序的候选选择语言，并按调用方提供的时区转换时刻。传输入口负责 HTTP 权重、gRPC 元数据和偏好来源排序。
- 稳定错误标识由服务契约定义。Go 错误链沿用标准库，Kratos 的 Reason 与传输状态翻译归框架边界。资源查找用消息键，并保留原始错误链的所有权。[Go errors](https://pkg.go.dev/errors) · [Kratos Errors](https://go-kratos.dev/docs/component/errors/)
- 时钟、重试、ID、日志、流缓冲与生命周期组件只有在实际调用表明标准库或现有实现无法兑现共同承诺时，才按新切面评估。[分层 ADR](../adr/0004-layer-and-module-boundaries.md)

每个切面先写可观察契约，再实现并用失败路径验证。运行竞态检查、包依赖检查与针对热点的基准。说明证据对应的是包能力、跨进程集成还是完整应用。真实传输、Agent Provider 和镜像行为由相应的后续纵切验证。

## 首版验收记录

在 Go 1.25.0、macOS arm64 下运行 `go test -race ./...`、`go vet ./...` 和包依赖检查。旧实现的运行时回归在回调退出时超时，修订后能观测到原始 panic 和后续回调。语言包的可运行示例验证同一次请求先选择繁体中文，再分别返回繁体中文正文和英文回退文案。

复盘确认包能力可以独立使用，接口只传闭包、语言标签和资源快照。语言匹配使用纯 Go 的 `golang.org/x/text/language`，其余 Core 逻辑使用标准库。网络协议、外部 SDK、翻译文件读取与热更新由上层拥有。完整服务路径仍由首条应用纵切验收。
